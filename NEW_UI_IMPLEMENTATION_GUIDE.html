4) Where to Change What (Behavior, UI, Titles)

Change type Primary place to edit Notes
Route mount or host behavior routes/new/index.js Controls serving under /new.
Sync behavior, hash bridge, logo fallback scripts/sync-new-ui.js Used by npm run new-ui:sync.
Screen titles / page-level copy new-ui-source/src/pages/*.tsx Reference source only unless rebuilt into bundle.
Component layout/styling new-ui-source/src/components/** and new-ui-source/src/index.css Reference source only unless rebuilt into bundle.
Immediate runtime hotfix new-ui-bundle/assets/*.js Minified bundle patch; fast but hard to maintain.
What browser actually runs public/new/assets/*.js Do not edit directly; regenerate via sync from bundle.
Current repository state: new-ui-source is a source snapshot for reference; runtime is sourced from new-ui-bundle. Any source change must be propagated into a new bundle and then synced.

5) Update Workflow

Safe/standard path

  • Update UI/behavior in source branch/workspace.
  • Produce updated static bundle.
  • Replace new-ui-bundle/ contents in this repo.
  • Run npm run new-ui:sync.
  • Validate pages and endpoint behavior in Adapt.
  • Update this guide + push.

Emergency hotfix path

  • Patch new-ui-bundle/assets/*.js directly.
  • Run npm run new-ui:sync.
  • Document patch reason and follow-up source fix task.

6) Quick Troubleshooting

New UI does not load

  • Check public/new/index.html exists.
  • Run npm run new-ui:sync.
  • Confirm route mount in routes/new/index.js.

Logo broken

  • Check public/new/adapt-logo.jpeg exists.
  • Check public/adapt-logo.jpeg root fallback exists.
  • Hard refresh browser (Ctrl+F5).

Hash link opens wrong page

  • Verify hash bridge map in scripts/sync-new-ui.js.
  • Re-sync and hard refresh.
